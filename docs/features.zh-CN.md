# Tabgent 使用指南

[← 首页](../README.zh-CN.md) · [English](features.md) · **简体中文**

从你正在使用的网页开始，告诉 Tabgent 你想解决的问题。下面通过食谱、出游、PDF 和网站搜索等示例，介绍具体用法。

## 按家里的人数调整食谱

食谱能做十二张煎饼，但你只需要六张。让助手换算用量，把步骤整理得更容易照着做。

来源：[Good Food — Easy pancakes](https://www.bbcgoodfood.com/recipes/easy-pancakes)

![按家里的人数调整食谱](assets/zh-CN/cooking.png)

可以这样问：

> 我只想做6张煎饼。请根据这份食谱把材料用量减半，整理一份简短的材料清单、制作步骤和所需时间。只根据当前食谱，用中文简洁回答。

打开食谱后直接提问，也可以先选中材料表。需要换算单位或列购物清单时，继续补充要求即可。

## 安排一次出游

把两家博物馆官网打开，告诉助手孩子的年龄和你关心的条件，请它比较门票、预约要求和适合孩子的活动。

来源：[V&A South Kensington](https://www.vam.ac.uk/south-kensington/visit) · [Young V&A](https://www.vam.ac.uk/young)

![安排一次出游](assets/zh-CN/travel.png)

可以这样问：

> 想带7岁的孩子在伦敦玩一天，正在考虑 V&A South Kensington 和 Young V&A。请阅读已打开的官方页面，比较是否免费、是否需要预约以及适合孩子的活动，只比较这三项，给出建议并附参观信息链接。不要预订。用中文简洁回答。

把官网放在同一个浏览器窗口，选择 Current window（当前窗口）。出行前再次确认最新信息；这个例子不进行预约。

## 使用 PDF

看不懂论文里的架构图？可以让助手结合原文解释，并把关键段落高亮留在文档里。

来源：Vaswani 等人，《[Attention Is All You Need](https://arxiv.org/abs/1706.03762)》，第 3 页图 1。

![使用 PDF](assets/zh-CN/pdf.png)

可以这样问：

> 请阅读这篇论文第 3 页和图 1，用中文通俗解释编码器、解码器各做什么，为什么解码器要使用掩码注意力。高亮第 3 页选中的原文，回答简洁一些。

选中 PDF 文字后提问，助手能结合页码定位。用 Tabgent 工具条的 **高亮** 或 **询问 AI** 标记的原文会保存到[阅读笔记](#划线提问保存阅读笔记)；用阅读器自带标注工具添加的高亮、批注和修改只保存在下载的副本中，完成标注后，请使用阅读器的下载按钮保存。图片扫描件可能无法准确选中文字；PDF 无法打开时，可以切换到 Chrome 阅读器，但精确高亮需要 Tabgent 的 PDF 阅读器。在 Mac 上双击打开的 PDF，开启文件访问后也会使用 Tabgent 的 PDF 阅读器（见[在 Chrome 中打开的文件](#划线提问保存阅读笔记)）；也可以从资料库打开。上传附件可以用于阅读，但不会自动打开标注阅读器。论文版权归原作者所有。

### 点击引用查看原文

PDF 链接可以携带页码和原文片段。在 Tabgent 中打开后，会定位文字并显示临时搜索高亮：

```text
https://example.com/paper.pdf#page=3&search=ENCODED_TEXT&phrase=true
```

将 `ENCODED_TEXT` 替换为经过 `encodeURIComponent` 编码的原文，原网址的查询参数保留在 `#` 前。页码指定查找的起始位置，不会把搜索限定在这一页。这不会写入永久标注；没有可搜索文字的扫描件可能无法匹配。

## 读懂网页里的说明

软件出了问题，帮助文档又很长。这个例子让助手解释 Zotero 的文献同步与附件同步，并给出排查步骤。

来源：[Zotero — Syncing](https://www.zotero.org/support/sync)

![读懂网页里的说明](assets/zh-CN/read.png)

可以这样问：

> 我在两台电脑上用 Zotero，但第二台电脑没有 PDF。请阅读这份官方文档：数据同步与文件同步有什么区别，300 MB 限额会限制我的文献条目吗？用中文简洁解释，给我三个排查步骤。

## 对比不同方案

选方案时，价格之外还有使用条件。这里比较研究小组共享 1 GB PDF 时，Zotero Storage 与 WebDAV 是否适合。

来源：[Zotero Storage](https://www.zotero.org/storage) · [Syncing](https://www.zotero.org/support/sync)

![对比不同方案](assets/zh-CN/compare.png)

可以这样问：

> 阅读已打开的两份 Zotero 官方页面。我需要和研究小组共享 1 GB 的 PDF。用小表格比较 Zotero Storage 与 WebDAV：是否支持群组文件、空间由谁提供、相关费用。仅根据这两个页面给出建议，不要购买。用中文简洁回答。

## 让助手操作网站搜索

知道搜索条件，却不想逐项设置？把标题关键词和年份交给助手，让它操作 arXiv 的高级搜索，找到对应论文。

来源：[arXiv Advanced Search](https://arxiv.org/search/advanced)

![让助手操作网站搜索](assets/zh-CN/act.png)

可以这样问：

> 请操作这个 arXiv 搜索表单，查找 2020 年标题包含 Retrieval-Augmented Generation 的原始论文。设置标题字段和年份，然后执行搜索。用中文简短给出匹配的标题和链接，不要使用其他搜索服务。

## 划线、提问，保存阅读笔记

阅读网页、PDF 和 EPUB 电子书时，Tabgent 会把你的高亮和讨论保存为 Mac 上的 Markdown 文件。下次重读，或者在读另一篇文档时提问，都可以在这些记录的基础上继续。

**高亮一段原文。** 在网页、在 Chrome 中打开的本地文件、Tabgent 的 PDF 阅读器或 EPUB 阅读器中选中文字，选区旁会出现一个小工具条：

- **高亮**：保存这段原文，并用柔和的黄色标出。
- **询问 AI**：同样保存这段原文，同时打开侧边栏、附上引用，开始一段关于这条高亮的对话。输入问题后可以继续追问。

点击已高亮的文字，可以就它提问、查看讨论，或选择 **删除**。即使 Codex 未连接，高亮也能保存；重新打开网页、PDF 或书时，高亮会自动恢复。

**写下自己的笔记。** 点击已高亮的文字，选择 **添加笔记**，写下你对这段文字的想法。按 ⌘ Enter 或点击 **保存笔记** 保存，按 Esc 取消；保存空笔记即删除笔记。之后再点击这段文字，笔记会显示在操作按钮上方，选择 **编辑笔记** 可以修改。侧边栏 **Page chats（网页会话）** 中的高亮列表和 EPUB 阅读器的高亮列表也会显示笔记，并且可以在侧边栏列表中添加或编辑笔记。和高亮一样，保存笔记不需要 Codex 在线。

**Codex 知道哪些上下文。** 每条消息都会告诉 Codex 你正在读哪篇文档、高亮的原文和位置、前后文、你对这条高亮写的笔记，以及此前保存的关于它的讨论。你的笔记会被标明是你自己的看法，方便 Codex 区分你的观点和作者的观点。Codex 会被要求围绕原文回答，区分作者观点和它自己的推断，并指出所引用的位置。

**从上次停下的地方继续。** 每条高亮都有自己的对话。点击这段文字并选择 **查看讨论**，即可打开之前的问答并继续追问，重启 Chrome 之后也可以。侧边栏的 **Page chats（网页会话）** 也会列出本页的高亮：点击可以滚动到原文位置，也可以从这里打开讨论。

**针对整篇文档提问。** 不选中文字直接提问，就是围绕当前网页、PDF 或书的讨论。输入框旁的按钮显示这段对话保存到哪里：某条高亮、**页面笔记**，或 **不保存**。点开它可以打开或关闭 **保存到阅读笔记**。如果这篇文档已有笔记，默认会保存。关于高亮的对话始终会保存。

**笔记文件夹。** 笔记默认保存在 `~/ReadingVault`，也可以在同一个菜单中改用其他文件夹；已保存的笔记不会被移动。每篇文档有自己的文件夹：网页以及 Mac 上的 Markdown、文本和 HTML 文件在 `Articles/` 下，PDF 和 EPUB 在 `Books/` 下。从资料库打开的 PDF 或 EPUB，以及高亮过的 Mac 上的 PDF，还会把文件本身（`original.pdf` 或 `original.epub`）和文字保存在这里：`pages/` 中每页一个 Markdown 文件，或 `chapters/` 中每章一个。其中的 `highlights.md` 先写标题和来源，然后依次列出每条高亮的位置（章节标题、页码或章节）、时间、引用的原文、写在 **笔记** 下的你的笔记，以及下面的对话；针对整篇文档的提问保存在 **文档对话** 下。`anchors.json` 保存用于恢复高亮的位置信息。这些文件可以用 Obsidian、VS Code 或任意编辑器打开；你在 Tabgent 标记的区块之外写下的内容会被保留。高亮笔记请在 Tabgent 中修改：直接在文件里改动的笔记不会被读回，下次在 Tabgent 中保存这条笔记时会被替换。

**结合以前读过的内容提问。** 例如可以问：“我以前读过类似观点的内容吗？” Codex 会用一个无需批准的只读工具检索笔记文件夹，然后说明用到了哪篇文档、哪条高亮和哪个文件；找不到相关内容时也会如实说明。这个工具只读取 Tabgent 写入的笔记文件，不能修改它们。在允许执行命令时，Codex 也可能用命令行检索这个文件夹；这些命令遵循你选择的权限模式，不限于 Tabgent 的笔记文件。检索按关键词匹配，提问时使用笔记中出现过的词效果更好。

**按需读取更多原文。** 只有问题需要时，Codex 才会读取更多原文：例如你问到的 PDF 页面，从导入的 PDF 保存的页面文本中读取某一页（标签页关闭时也可以），或从随书保存的章节文本中读取 EPUB 的某一章。

**资料库。** 右键点击工具栏中的 Tabgent 按钮，选择 **打开资料库**；也可以在侧边栏的阅读笔记菜单中选择 **打开资料库**，在当前网页旁边打开它。资料库按最近更新排序，列出笔记文件夹中的所有文档：网页、本机文件、在线 PDF、导入的 PDF 和 EPUB 电子书，并显示类型、作者或网站、高亮数量和最近更新时间。点击即可重新打开：网页打开原地址，Markdown、文本和 HTML 文件从它在 Mac 上的位置打开，在线 PDF 在 Tabgent 的 PDF 阅读器中打开，导入的 PDF 和电子书从笔记文件夹中的副本打开。

**Mac 上的 PDF。** 在资料库中选择或拖入 PDF 文件（不超过 100 MB）。Tabgent 会把它复制到笔记文件夹，保存为 `original.pdf`，并在 PDF 阅读器中打开；高亮、笔记、**询问 AI** 和保存的讨论都与在线 PDF 相同。之后无需原文件即可从资料库重新打开；再次打开同一个文件会使用已有的副本。在 macOS 上，每一页的文字会通过 PDFKit 保存为 `pages/NNN.md`，即使关闭了标签页，Codex 也能检索和阅读这篇论文。扫描页没有文字；受密码保护的 PDF 在阅读器中输入密码后即可打开，但不会保存页面文字。PDF 以其标题命名，没有标题时使用文件名。

**在 Chrome 中打开的文件。** 在 Mac 上双击 PDF、Markdown、文本或 HTML 文件，照常在 Chrome 中阅读，无需导入。选中文字即可 **高亮** 或 **询问 AI**，也可以写笔记、针对整个文件提问，和在网页上一样。PDF 会在同一个标签页中切换到 Tabgent 的 PDF 阅读器（地址栏显示 Tabgent 的地址，与在线 PDF 相同）；点击 **用 Chrome 阅读器打开** 可以让这个标签页改回 Chrome 自带的阅读器。Markdown、文本和 HTML 文件保持 Chrome 的显示方式，Markdown 以纯文本显示。

- **只需授权一次。** Chrome 只有在你为扩展打开 `chrome://extensions` 中的“允许访问文件网址”后，才允许它读取文件。未开启时第一次打开文件，Tabgent 会打开一个说明页面，并提供直达 Tabgent 设置的按钮；在这类文件上，侧边栏也会显示提醒。开启后，已经打开的文件无需刷新即可使用。
- **PDF 的笔记跟随内容。** PDF 以文件内容的 SHA-256 命名，与资料库导入相同。第一次高亮或保存讨论时，它会连同页面文字复制到笔记文件夹，保存为 `original.pdf`；因此移动或重命名文件后笔记仍在，资料库可以重新打开它，导入同一个文件也共用这些笔记。只打开 PDF 不会保存任何内容。超过 100 MB 的 PDF 会保留笔记，但不保存副本。
- **文本文件的笔记跟随路径。** Markdown、文本和 HTML 文件会随着编辑而改变，所以它们的笔记属于 `file://` 地址，和网页的笔记一样；编辑后，高亮会像网页一样重新找到原文。移动或重命名文件后，笔记仍留在原来的地址下。
- **Codex 能做什么。** Codex 可以读取你打开的文件（PDF 按页读取），并把文件路径视为页面地址。它不能在文件中点击或输入，也不能自行打开文件；文件夹列表（`file:///…/`）不会被当作文档。

**EPUB 电子书。** 在资料库中选择或拖入 EPUB 文件。这本书会复制到笔记文件夹，每一章的文字另存为一个 Markdown 文件，再次打开时回到上次的位置。阅读器提供目录和高亮列表、字号调整，以及分页或滚动阅读。书中的脚本，以及远程图片、字体和样式都会被拦截。

**限制。** 网页高亮只支持页面本身，不支持页面内嵌的框架；安装或更新 Tabgent 之前已经打开的标签页需要刷新。PDF 高亮需要使用 Tabgent 的 PDF 阅读器，它打开在线（HTTP 或 HTTPS）PDF、从 Mac 打开的 PDF 和从资料库打开的 PDF，且文字需要可以选中。从 Mac 打开的文件需要开启“允许访问文件网址”；未开启时它们照常在 Chrome 中打开，但无法使用 Tabgent。如果 Chrome 未运行，双击的 PDF 会先短暂显示 Chrome 自带的阅读器，再切换到 Tabgent 的阅读器。在线 PDF 和 Mac 上同一文件的副本是两篇独立的文档，各自保存笔记。打开 Mac 上的 PDF 需要连接器；页面文字需要 macOS PDFKit，扫描页不会进行 OCR 识别。导入的文件保留在保存时的笔记文件夹中：改用其他文件夹后，需要在资料库中重新选择文件。固定版式的 EPUB 会保存高亮，但不会在书中显示。如果找不到某条高亮对应的原文，Tabgent 会保留笔记并标记为未找到，而不会错误地标注其他文字；目前还不能重新定位。存储和发送的数据详见[隐私与权限](privacy.md)。

## 把相关材料一起交给助手

- **针对原文提问：** 在网页选中文字，再到侧边栏提问。也可以右键点击选中的文字，使用 **Quote in Agent（引用到助手）** 把它带入对话。
- **确认正在讨论哪个页面：** 输入框旁的标签页图标显示下一条消息对应的页面。如果多个标签页共用一个会话，可以在发送前点击查看详情。
- **附上自己的材料：** 点击附件按钮，粘贴文件或图片，或直接拖入输入框。图片支持预览；PDF、DOCX 和文本附件可以结合网页一起阅读。每条消息最多附加 10 个文件，每个不超过 10 MiB。扫描版 PDF 可能没有可读取的文字。
- **直接使用网站：** Tabgent 可以读取网页、查看截图、点击控件、填写表单、选择选项、滚动和切换页面。鼠标操作时会显示虚拟指针。不同网站的支持情况可能不同。

## 让网页和会话保持关联

打开 **Page chats（网页会话）**，查看与当前网址关联的对话。发送消息时，该网页才会与会话建立关联；仅仅切换网页不会建立关联。同一个会话里聊过多个网址，就能从这些网页各自的历史列表找到它。列表不显示空会话。

从链接打开新标签页并产生关联会话时，原会话会记录新会话，新会话也会显示自己的来处。点击会话名称即可切换到对应标签页。这样能顺着网页找回之前的工作，但不会把原会话的全部内容复制进新会话。浏览器重启后，可能无法自动回到原来的标签页。

点击 Agent 顶部的 **+**，在当前页面开始新会话。需要更多阅读空间时，点击展开到新页面的按钮，在完整的 Agent 页面继续当前对话。

## 任务进行中也能随时调整

- **查看进度：** 展开活动记录，查看执行步骤和工具活动。任务包含计划时，对话中也会展示计划进度。
- **排队补充：** 助手工作时可以继续发送要求；待发送消息可以编辑或删除。
- **立即调整：** 使用 **Steer** 把要求交给当前任务，不必等下一轮。
- **停止：** 点击停止按钮。已经完成的操作不会因此撤销。
- **先梳理计划：** 输入 `/plan` 切换到计划模式，再描述任务。再次使用可退出计划模式。
- **围绕目标继续工作：** 输入 `/goal` 设置目标和可选的 token 用量上限。目标控件支持查看进度、修改、暂停、恢复或清除。此功能需要你的 Codex 版本支持。

## 按你的习惯使用

**模型与思考强度。** 点击输入框旁的模型选择器，在同一个菜单中选择模型及思考强度。可用选项来自你的 Codex 配置。

**批准方式与浏览器范围。** 可以选择 **Ask for approval（请求批准）**、**Approve for me（代为审批）** 或 **Full access（完全访问）**。浏览器操作范围另行选择 **Current window（当前窗口）** 或 **All windows（所有窗口）**；这项范围设置不限制 Codex 的其他工具和已连接服务。各项设置的边界详见[隐私与权限](privacy.md)。

**技能和其他工具。** 输入 `/skills` 浏览及管理可用技能，或输入 `$` 为消息选择技能。会话也可以使用 Codex 原生工具（包括网页搜索），以及已配置的应用或 MCP 集成。具体取决于 Codex 版本、模型、权限和配置；Tabgent 不会自动替你连接新的服务。

**保留结果。** 点击回答下方的 **Copy（复制）**，或输入 `/export`，将会话里的用户消息和助手回答下载为 Markdown。导出内容是文本，不包含附件备份或浏览器录像。输入 `/rename` 可以给会话起一个容易辨认的名字。回答支持展示表格、代码和数学公式。

**管理较长的对话。** `/status` 可查看模型及可用的上下文用量信息；`/compact` 会请 Codex 压缩对话上下文，减少继续聊天时占用的空间。
